## 只找真正的错误

只报告有证据、会在真实使用中让用户做错决定或做错事的错误。每一项都要能在本说明的报告文字或报告 JSON 里指出依据。

1. 数字：报告文字里的数字或结论，与报告 JSON 里工具算出的结果不一致。培养报告是花费、缺口、累计结果或「库存能支持到第几步」（`steps[].cost`、`steps[].cumulative`、`supportedThrough`、`gaps`）；基建报告是验收门结论、校验错误和警告、容量、床位、心情上限和效率（`check`、`plan`、`operators`）。
2. 资料：推荐理由引用的资料没有这么说、说反了，作者、日期、来源对不上，引用了不存在的依据编号，或把只有标题的检索结果当成帖子观点。
3. 事实与推断：把推断写成已核实的事实，把未知当成 0 或已满足，把未核实的验收门说成通过，或漏掉了工具标出的待核项、不确定项。
4. 顺序与偏好：步骤顺序或排班安排和用户说明的玩法优先级、目标矛盾而没有解释；用的是假设却没有标明。
5. 边界：建议或暗示抽卡、礼包、付费、登录，碎石或使用理智药、临期药，替用户操作设备或游戏；把审查通过或批准说成已经执行；让 maa-account 写 MAA 配置。

不要报告：措辞、格式和风格；「可以更好」但指不出具体错误的意见；正式使用中几乎不会出现的情形；与报告结论无关的细节。工具计算本身（培养报告是工单 14 的共享缺口计算，基建报告是共享排班检查）不在本次审查范围，你核对的是报告文字与这些数字、与引用资料是否一致。

