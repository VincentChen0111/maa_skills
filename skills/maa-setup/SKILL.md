# maa-setup

开始前确认相邻 `../maa-core/scripts/` 中的 `preferences.ts`、`setup.ts`、`setup-connection.ts`、`setup-download.ts`、`maa-config.ts`、`maa-process.ts`、`credentials.ts` 存在。缺少 core 时停止：Codex 使用自带 skill-installer，从 `VincentChen0111/maa_skills` 同一版本安装 `skills/maa-core` 与 `skills/maa-setup`；Claude Code 使用原生市场 `/plugin marketplace add VincentChen0111/maa_skills`、`/plugin install maa-skills@maa-skills` 安装完整插件，已有安装用原生更新入口更新。

1. 先确认当前宿主是 Windows，运行 `node --version` 确认主版本是 24。没有 node 或脚本无法运行时，按 [接入接口](references/setup.md) 给 Node 官方下载页并说明选 24.x，由用户自己下载安装，装好后再继续；不改用其他命令代下载。node 能运行但主版本不是 24 时，可以按第 3 步的下载流程处理 Node（`plan`／`download` 只对 `program: "node"` 放行）。可运行后，调用 `node <本目录>/../maa-core/scripts/preferences.ts read`，标准输入传 `{"currentLanguage":"<用户当前语言的 BCP 47 标签>"}`。按返回语言回复；未设语言时用用户当前语言。读取设置失败也继续下一步只读 check，用用户当前语言报告诊断。
2. 读 [接入接口](references/setup.md)，运行 `setup.ts check --json`，设置已保存后再运行 `setup.ts downloads --json` 查看下载与解压状态；每次（包括中断后继续）都重新读取现场，已经正常或已经完成的步骤跳过。依次说明 Windows GUI MAA、国服、Node、设置文件、私有目录和版本的检查结果。设置损坏或不可读时按 check 返回的原因、修法和执行者处理，保留原文件，等待用户修复；不能当成首次接入询问或覆盖，也不猜私有目录。只有首次需要时询问偏好语言和私有目录（默认用户目录下 `.maa-skills`）；用户本次已给的答案直接使用，已有设置沿用、不重复提问。语言问过但暂未选时，经偏好脚本记录 `languageAsked: true`。结构化设置只交给 `preferences.ts set`，不直接写设置文件；私有目录选择仓库、skill 和 MAA 安装目录之外。随后调用 `setup.ts prepare --json` 创建私有目录骨架并记录现场结果，它只创建目录及 `setup-environment.json`，保留已有文件。已有 MAA 时询问目录，可以先用 `check` 的 `maaDirectory` 检查，再经 [偏好接口](../maa-core/references/preferences.md) 保存；配置缺失或损坏时让用户在 MAA GUI 初始化／检查，保留原文件。
3. 缺少 MAA、模拟器、adb 或 Node 时走下载流程，一个程序一份方案：
   - 调用 `setup.ts plan`，原样告诉用户文件名、版本及其出处、官方来源和官方页面、大小（`sizeKnown: false` 时明确说大小未知）、有无官方校验值，以及每一步由 skill 还是用户来做。adb 方案带 Android SDK 许可协议链接：请用户自己阅读并决定是否接受。模拟器先让用户从 MAA 支持列表选厂商，再请用户在厂商官方页面点下载按钮，从浏览器的下载列表里复制这个按钮实际触发的下载地址（不是页面链接；MuMu 的按钮没有可复制的页面链接，只能这样取），并读出官方页面或安装包文件名上的版本号，然后传 `vendor`、`url`、`version`。返回 `unofficial-source` 时不下载，让用户在官方页面自己下载。脚本不能下载的厂商：`bluestacks-cn`（蓝叠 5，官方服务器拒绝脚本请求）；用户选它时不用取地址，直接说明脚本不能下载它。`plan` 或 `download` 返回 `source-refused` 时，告诉用户：官方服务器拒绝了脚本的下载请求，脚本不会换请求头或伪装成浏览器重试，这次不下载；请用户在自己的浏览器里从该厂商官方页面下载安装包，然后从 `run-emulator-installer` 这一步继续（用户自己运行这个安装程序，不需要把文件交给脚本），之后照常走模拟器设置、游戏客户端和第 4 步的连接。不要为了下载去加 Referer 或其他请求头，也不要换别的地址或镜像。
   - 展示方案后停下，等用户对这一份方案明确确认，才调用 `download`，传方案的 `planId`、`fingerprint` 和用户确认的原话 `reference`；adb 只在用户明确说接受该许可协议时加 `termsAccepted: true`。用户发起安装、偏好、之前对话里的同意、对别的版本或别的方案的同意，都不算这次确认；绝不替用户编写确认原话或接受协议。用户拒绝或没有回答时不下载，说明还缺什么。
   - 一份方案只能下载一次。返回 `plan-changed`、`plan-already-used`、`failed`，或 `downloads` 显示 `interrupted`、`failed`、`download-invalid` 时，都不算已下载；需要重新 `plan`、重新展示并重新获得确认。`downloaded` 不等于已安装。
   - 下载完成后：MAA 和 adb 调用 `install`，`target` 是用户选的空文件夹（MAA 不放在盘符根目录或 Program Files 下；adb 可以用 MAA 目录下的 `adb`），skill 只做解压。Node 安装程序、模拟器安装程序、依赖库安装、MAA 首次启动设置、模拟器里的 adb 开关、安装游戏客户端和登录都由用户自己做；skill 不运行安装程序、不替用户接受条款、不输入游戏账号、不操作设备。用户做完后，MAA 目录经 `preferences.ts set` 保存，再回到第 2 步重新检查；adb 解压后在第 4 步用 `adbPaths` 指定。
4. 使用 `setup.ts discover --json` 发现现有 adb 和本机模拟器地址。候选按序号、来源和状态说明，不输出真实路径、地址、完整配置或账号信息。零候选时让用户在模拟器／MAA 界面检查 adb 路径和本机连接地址；多个候选时明确让用户选择。来源不足以区分时请用户在本机界面选定后提供路径／地址，以标准输入限定候选；不按排列顺序猜测。单一候选或用户选定后，绑定返回的 `discoveryRevision` 和候选 `id` 调用 `test`。只测试 adb 传输，不点击、截图、登录或操作游戏，也不启动模拟器。
5. 连接测试通过，且本次需要保存连接设置时，调用 `apply`。该动作在共享脚本内重新发现、复测，再交统一写入器；只调整当前配置的 adb 路径、地址及关闭自动发现的两个开关，不改变连接预设／触控／登录。MAA 已关闭且无锁时，安装请求仍不代表关闭确认：明确告诉用户 MAA 已关闭，获得“没有在操作，可以写入”的单独确认后才传 `closedConfirmed: true`。若首次调用返回 `closed-confirmation-required`，等确认再调用；绝不为了让调用通过自行填 true。遗留锁交 maa-doctor 核对，未知结果不重放。
6. 最后调用 `setup.ts recheck --json`，传用户在第 4 步选定的候选 `candidate`（候选 id，不传 `discoveryRevision`；第 5 步写入和 MAA 启动都会改配置，旧指纹必然失效）。它重新检查 Node、MAA、adb，重新发现连接并按候选 id 找到同一个 adb 和地址后测试，再更新环境记录；返回 `candidate-unavailable` 表示这个候选已不在现场，回到第 4 步重新发现和选择。只有返回 `complete: true` 才能说接入完成；否则逐项列出 `pending` 和每项由谁来做，不把下载、解压或用户说“装好了”当成完成。说明 adb 测试只证明传输可用，MAA 识别／游戏任务尚未实机验证。未知版本或版本记录缺失只提醒，仍可接入；读取随包的验证记录，不把起点 skill 的历史经验当成本仓库实机已核。报告本次实际完成和待处理项。
7. 凭据是可选项，只在用户要用 NGA、森空岛账号或 B 站（实验性）相关功能，或 check 报告凭据过期／无法读取时处理。读 [凭据接口](../maa-core/references/credentials.md)，运行 `node <本目录>/../maa-core/scripts/credentials.ts check --json`（`setup.ts check` 附带的是同一组检查），按状态说明：保存了不等于可用，「尚未验证」要等第一次实际读取。需要设置或重新输入时，给出带实际路径和 `--language <用户语言的 BCP 47 标签>` 的 `credentials.ts input <nga|skland|bilibili>` 命令，请用户自己打开终端运行并按提示输入；agent 不运行 `input`、不加 `--stdin`、不替用户登录，也不请用户把 token、Cookie 或 SESSDATA 贴到对话里。用户已经贴出时不复述、不保存、不传给脚本，按接口说明提醒换新后在本地输入。设置森空岛前先说明两点：截至 2026-11-13 没有找到鹰角对第三方调用森空岛接口的公开表态，是否使用由用户决定；token 只用来读取账号数据。B 站说明是实验性的，不要依赖；森空岛社区公开调研不用账号凭据。用户说已完成后重新 check 报告状态。

用户发起安装即授权上面的检查、解压和接入步骤，但每次程序下载仍要先展示方案、取得这一份方案的确认。只写设置（经偏好脚本）、私有目录骨架、环境记录和下载记录、用户所选空文件夹里的解压内容、连接配置（经统一写入器）；凭据只由用户本人运行输入脚本写入；账号快照和建议报告交 maa-account。源石、抽卡、礼包、付费、登录和设备操作始终不执行。
