## MAA 版本

下面两行由 `node scripts/maa-version-check.ts notes` 按随包核实记录（`skills/maa-core/references/verified-versions.json`）生成，发布时检查脚本逐字核对：

MAA 源码已核：v6.22.0

MAA 实机已核：无（没有在真实 MAA、模拟器和游戏上核对过的版本）

- **源码已核**：v6.22.0。意思是本仓库依赖的每一条 MAA 行为，都在 v6.22.0 的源码上对过指纹（[依赖条目](../maa-dependencies.json)，做法见 [MAA 版本跟踪的来源](../maa-version-sources.md)）。源码相同不等于在真实环境里跑通过。
- **实机已核**：无。本仓库还没有在真实 MAA、模拟器和游戏上核对过任何版本。离线测试、合成 GUI 用例、宿主替身和机器评分都不算实机核对；起点 skill 在 MAA v6.21.4 上的实测经验是另一个项目的历史，也不算本仓库的实机核对。
- `maa-setup` 和 `maa-doctor` 按这份记录提醒：装的 MAA 版本不在列表里时只提醒，不拒绝运行；装的版本低于某个源码已核的正式版时提醒升级，并说明那个版本是否实机已核。升级由用户自己完成。

## 包含什么

五个 skill 和一个共享目录，正文都是中文，两个宿主共用：

- `maa-help`：只用文字回答能做什么、用哪个 skill、怎么安装和更新。
- `maa-setup`：接入或补齐 Windows 图形界面版 MAA、国服模拟器、adb 和 Node 24；下载前先展示官方下载方案，用户确认后才下载；凭据由用户在自己的终端输入。
- `maa-account`：账号快照（MAA 本地识别结果，或森空岛只读）、培养成本与缺口、基建技能查询、带出处的只读调研、带独立审查的培养建议与基建建议。
- `maa-daily`：按当次交办或已批准的报告维护日常队列、提醒、定时，准备指定关卡作业并跟踪结果，专精排程，应用已批准的基建排班。
- `maa-doctor`：分组检查、日志分析与转介、遗留写入核对与恢复，修法逐项点名批准。
- `maa-core`：操作类 skill 共用的脚本，不直接处理请求，要和操作类 skill 装同一版本。

只支持 Windows 上的 MAA 图形界面版和国服；共享脚本需要 Node 24。不打包 MAA 的代码和资源、游戏数据、企鹅物流和一图流的数据，用的时候再读取。

## 安装与更新

- Claude Code：`claude plugin marketplace add VincentChen0111/maa_skills`，再 `claude plugin install maa-skills@maa-skills --scope user`。插件以仓库根目录为插件，全部 skill 和 `maa-core` 一起装好。
- Codex：用自带的 skill-installer 按 `skills/<名称>` 安装，`maa-core` 要和操作类 skill 一起列出，固定到这个版本的标签。安装器不覆盖已有目录，更新时先在临时目录装好验证，再整体重装全部 `maa-*` 目录。
- 详细步骤见 [宿主与安装](../../skills/maa-help/references/hosts.md)。
