# 26 H4 合并后的 CI 修复：独立审查

日期：2026-11-15。范围 `9896727..22c0a33`，一个提交。

## 起因

PR #100（H4）在 CI 没通过的情况下就被合并了，这是协调者的失误：等 CI 的命令后面直接串了合并，没有按 CI 结果拦住。ubuntu 任务里 `tests/doctor-handoff.test.ts` 失败；windows 任务没有失败，是被矩阵的 fail-fast 取消的，日志里是 `The operation was canceled`。

## 根因与修复

- **根因。** `doctor-reconcile-approved` 收尾那次 `doctor.ts check` 在 `expectedInvocations` 里省略了退出码，等于要求退出 0。可在 Windows 以外，平台检查（`platform` / `windows-required`）是错误行，`doctor check` 退出 1。
- **为什么本地发现不了。** `doctor-scenarios` 里对应的 CLI 测试只在 Windows 上跑。
- **修复。**
  - 收尾 check 的退出码改用 `expectedExitCode`，只在不为 0 时写出。所以 Windows 上的场景定义逐字节不变，场景、载荷和运行器指纹都不变，评测不受影响。
  - 去掉这个 CLI 测试只在 Windows 上跑的限制。

## 审查

一名独立审查员，一轮通过，P1 0、P2 0、P3 0。审查员核对了：
- **根因属实。** 用模拟 Linux 平台的预加载复现，失败与 CI 日志逐字一致；修复后模拟 Linux 和 Windows 下都通过。
- **Windows 上不变。** 审查员自己算了哈希：`doctor-reconcile-approved` 的定义和整个场景目录在 Windows 上的哈希都没变。
- **没有别的同类假设。** 其它 doctor 和 daily 场景里没有写死平台退出码的地方。

未验证：没有在真实 Linux 上运行（本机没有 WSL 发行版），以本 PR 的 ubuntu CI 为准。
