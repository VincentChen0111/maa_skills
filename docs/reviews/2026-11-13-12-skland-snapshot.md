## 第一轮

结论：不通过，两条 P2、一条 P3。

审查员核对后认为以下各点正确：
- **只读边界**：只有两个固定主机；只有授权码换取两步用 POST，其余都用 GET；不跟随跳转，单次请求有超时。
- **秘密与账号标识**：角色号只在内存里拼进查询串；错误只带固定代码；快照和输出里没有 uid、昵称或头像。
- **事实核对**：签名链、接口路径和错误码已对照两个 MIT 公开项目的固定提交。
- **凭据规则**：凭据只经 09 的入口读取和记录；只有授权码换取被拒才记过期。
- **共用写入**：共用的写入函数没有改变工单 11 的行为。

| 意见 | 处置 | 理由 |
| --- | --- | --- |
| P2：同一次读取里重新换取已经成功，数据接口仍返回 10000 或 10002 时，仍把 token 记为过期 | 接受 | 授权码接口刚接受了 token，问题在签名或时间。用户会被要求重新粘贴一个可用的 token |
| P2：外层回复是 code 0 就按成功保存。玩家信息的结构已经变了时，会用空快照替换已有快照，也不给修法 | 接受 | 违反验收第 4 条「不伪造新快照成功」，与用户文档相反 |
| P3：养成接口请求失败时，仍用仓库未知的新快照替换旧快照，这条规则也没有登记 | 接受 | 会丢失数据，与规格和文档写的「读取失败不写新快照」不一致 |

修复：
- `f4ac638`：
  - 新增状态 `signature-rejected`，修法 `check-system-time`，凭据状态不变；
  - 玩家信息缺少核对过的干员结构时，整次读取报 `response-invalid`，不写入；
  - 部分读取不替换已有快照，只有第一份快照可以是部分读取。
- `88636ad`：规格正文和两张来源表、用户文档、参考文档、技能说明、验证记录同步。

## 第二轮

结论：不通过，一条 P2、一条 P3。审查员核对后认为第一轮三条修复都按声明实现。

| 意见 | 处置 | 理由 |
| --- | --- | --- |
| P2：code 0 的回复里某个域为空（空列表，或基建房间字段全部改名）时，这个域被当成读到，`import` 用空数据替换已有快照并报 `saved:true` | 接受 | 有离线复现。与第一轮 P2 是同一类缺陷，触发复发规则 |
| P3：code 0 的回复里缺少某个域（接口改名）时，修法给「稍后再试」 | 接受 | 接口不改回来，用户会一直被要求重试，永远得不到「报告问题」的提示 |

按同类缺陷复发规则，这次修复没有只补几条路径：
- 只留一个判定 `domainVerdict`，由它决定每个域算不算读到、能否替换已有快照。保留或替换、`saved`、`failedDomains`、修法、摘要和写入的覆盖状态，都只经过这一个判定。
- 修法统一由 `sklandRepair` 给出，按固定先后取一个。
- 加一个一致性测试，逐个列出三个域的各种产出路径，并逐个核对每个使用方。

修复提交为 `bb259ff`、`01b2167`。

## 第三轮

结论：有条件通过，一条 P3。

审查员核对后认为以下各点正确：
- **单一判定**：所有相关判断都经过这一个判定，旧函数已没有引用。
- **自列路径复现**：审查员自己列举了 13 种产出路径，每种都试了已有快照和没有快照两种情况。凡有空、缺失、无效或失败的域，已有快照都没被替换。
- **修法先后**：在进程内实测过，凭据过期加域缺失时给的是重新粘贴 token。
- **可选房间**：「会客室、人力办公室、训练室缺失视为未建造」与 MIT 公开项目声明的可选字段一致。只改这三个可选房间键名的接口变化，在正式环境几乎不会出现，审查员判为弱点、不报。
- **查询工具**：不可用的域按未知处理，不当作没有。
- **文档与隐私**：规格正文和两张来源表与代码一致；隐私检查通过。

| 意见 | 处置 | 理由 |
| --- | --- | --- |
| P3：首份快照的摘要说「没读到的部分标为不可用或无效」，但有可用条目的部分读取域实际连同数据以部分读取保存 | 接受，转 [Issue #51](https://github.com/VincentChen0111/maa_skills/issues/51) | 代理会据此告诉用户数据不可用。保存判定本身正确。已到三轮上限，按维护者规则转后续 |
