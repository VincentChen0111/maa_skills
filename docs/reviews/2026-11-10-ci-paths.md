# Windows CI 文件清单修复审查

日期：2026-11-10。固定基点：`786af12`。范围仅为 `scripts/files.ts`、`tests/privacy.test.ts` 与本记录。

工单 02 本地审查结束后，首次远程 [PR 30 CI](https://github.com/VincentChen0111/maa_skills/actions/runs/42761867866) 暴露 Windows 路径差异：Linux 通过，Windows 6/7，忽略的未跟踪文件进入隐私清单。该新发现作为独立修复包审查，不更改原包三轮记录。

## 复现与修复

通过公开导出函数、真实临时 Git 仓库，把同一个 Windows 目录改用大写路径传入。新增断言在修复前失败，多出被忽略文件的 `account-marker` 发现，与 CI 症状一致。原实现直接比较路径字符串，Windows 路径别名会错误落入无 Git 的遍历分支。

改为比较 `realpath` 解析出的实际目录，继续沿用 Git 的已跟踪与未忽略文件清单。定向测试由红变绿；类型检查通过；完整离线入口 7/7，tracker、隐私、元数据检查无发现。没有更改忽略规则，也没有访问真实账号或 MAA。

## 第一轮

新上下文的单一审查员读取自包含 brief、规格、贡献约定与限定 diff。Standards：0 项；Spec：0 项。确认实际目录比较消除误入递归扫描的问题，Git 清单仍含已跟踪的忽略文件，解析失败会阻断检查。

审查员在获准写临时 Git 元数据后，独立运行完整离线入口 7/7、类型检查及 Windows 大写路径回归，均通过。首次沙箱 `git init` 返回 128 的运行未记通过；修复前红测由实施者提供，审查员没有独立重放。无拒绝意见。最终结论：第一轮通过。
