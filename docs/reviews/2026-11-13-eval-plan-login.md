# 评测改用套餐登录的决定审查

日期：2026-11-13。基点 `8462913`，范围为提交 `c128259`（把决定写进工单 28 和规格）、`c8bb053`（第一轮修复）和 `2819798`（第二轮修复）。本包只改工单 28、工单索引和规格，不改脚本、skill、测试和评测；运行器在工单 28 交付之前仍只转发评测专用的 API key。

本包没有单独的工单：它执行维护者 2026-11-13 的决定，行为评测默认用维护者的 Claude 和 ChatGPT 套餐登录认证，不用 API key。原话登记在[规格](../spec.md)「默认值及其来源」和[工单 28](../issues/28-runnable-evaluation-auth-preflight.md) 的「决定」。原话没有覆盖的地方由协调者定为设计默认值，逐条登记在同一张表里。

每轮由一名新上下文的独立审查员读取自包含说明、AGENTS.md、CONTRIBUTING.md、规格相关章节和 diff，并各自取回两家的官方文档核对外部事实；第二、三轮只审修复。意见由协调者逐条判断，只接受真实错误。共三轮，达到上限。三轮里没有 P1、P2，没有被拒绝的意见。

## 第一轮

结论：通过，有四条 P3。

- 没有任何文字让 agent 或运行器输入凭据、复制或读取日常的登录文件、把登录路径写进记录，或者在 CI 里运行模型。认证预检的「其他」类别会停下整批；认不出来的用量上限消息落在原有的 `unverified` 类别里，不重试，也不记成场景失败。
- 维护者的原话在工单、索引和规格三处逐字一致；确认一事是转述，没有写成引语。
- OpenAI 的 CI 认证页有一句「不要用于公开或开源仓库」。审查员核对原文：它指的是在这类仓库的 CI 运行器上保存登录文件，没有涉及本机运行；工单的表述准确。

| 意见 | 处置 | 理由 |
| --- | --- | --- |
| P3：「出现清单之外的加载项记 `unverified`」和「升级宿主 CLI 后重新核实」只写在工单里 | 接受 | 违反规格的来源登记规则 |
| P3：`--bare` 那一行声称覆盖 bare 模式的全部范围，清单却漏了自定义命令、子代理和内置工具集 | 接受 | 去掉 `--bare` 后这三项不受限制 |
| P3：「登录目录落在私有目录之内就拒绝」没有写明私有目录从哪里得知 | 接受 | 照着测试实现会只核对场景里的那个目录 |
| P3：没有规定「被测模型读不到登录目录」的检查排在第一次带工具的套餐登录运行之前 | 接受 | 首批试运行会落在保护还没有核实过的宿主上 |

修复（`c8bb053`）：两条规则补进两张来源表和正文；隔离清单补上三项，并限制被测模型的工具；私有目录按产品自己的设置文件只读定位；规定读保护检查通过之前不用套餐登录运行任何带工具的场景，检查用登录目录里的合成哨兵文件，不用真实的登录文件。
