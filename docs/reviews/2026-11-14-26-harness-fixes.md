## 第一轮

结论：有条件通过，P1 0、P2 1、P3 1。审查员确认 H 本身没有安全缺陷：
- **垫片不会顶替真实宿主。** 试了 8 种 PATH 写法和 3 种显式垫片路径：只能在夹具里找到时记 `host-unavailable`，其余都解析到夹具外的真实文件。
- **替身只批准本次运行的说明。** 被改过的说明、任意文本、空输入、写在私有目录之外的说明都被拒绝。
- **环境探针失败时一律拒绝。** 子 shell 的环境去掉了 `CODEX_HOME` 和 `CLAUDE_CONFIG_DIR`。
- **合成凭据每次运行重新生成。** 只以 base64 写进响应文件；一致性测试遍历全部场景，确认凭据不以明文出现。

## 第二轮

结论：通过，P1 0、P2 0、P3 0。审查员核对了以下各项：
- **计数。** 未验证表合计 33 对，批次数合计 135；文中每处 32 都配了第 33 对的说明。
- **daily-unknown 的拒绝原因。** `ddd0ca8` 的 `skills/` 里没有 maa-doctor，所以这一对记 `payload-skill-missing`。
- **三个旧提交的附条件未验证。** 按 main 的提交顺序，788ac13、3ff4555、fc633d6 的 doctor 记录格式早于 10、25、08。
- **重定向不改字节。** 真实 `powershell.exe` 在代码页 65001 和 936 下，经 cmd `<` 重定向传入的说明与原文逐字节相同，相对路径、绝对路径都一样。
- **管道会改字节。** PowerShell 管道传入时，中文变成 `?`，65001 下还加 BOM。
- **测试不会启动真实 `codex`。** 退出 99 的守卫按 PowerShell 的目录优先规则判断，短路径 PATH 下也正确。
- **测试不留状态。** 父控制台的代码页不变，临时目录有清理。

文中指向包 P 记录的位置写成代码格式路径，没有写成链接，与链接检查器一致；两包都合入后可改成链接。
