## Spec

### R1-1 [P1] 保存执行资产时丢弃已经验证的替代分配

位置：`skills/maa-core/scripts/stage-jobs.ts:220-222`。

`matchStageJobs` 可以因组中一个成员 ready 而给整份作业 ready，但准备时原样保存全部成员，完全没有使用 `candidate.assignment`。探针中 A 精二 50 级、潜 1，要求潜 6，结果 blocked；B 精一 30 级、潜 1，要求潜 1，结果 ready。报告分配 B，`prepareStageJobs` 返回 complete，实际文件却仍有 A+B。固定 MAA 的潜能要求未被 Core 解析和编队校验，正常自动编队可选回练度排序更高的 A。于是已经被工具判不满足的成员仍能执行，违反逐成员核对后准备可执行作业的验收要求。

应把已核分配落实到可审查、哈希绑定的执行内容，或在不能保证时拒绝准备；不能依赖原生一定复现本工具的匹配结论。来源原文与派生执行内容的证据应分开保留。

### R1-2 [P2] 合法的 beta 最低版本永久被判为未核实

位置：`skills/maa-core/scripts/stage-jobs.ts:25-29`。

官方战斗协议明确允许 `minimum_required: "v6.8.0-beta.1"`。本机版本 `v6.21.4` 显然已满足这个最低版本，但正则只接受三段整数，探针得到 `unknown / version-unverified`，因而无法准备这份其他条件全部满足的作业。当前 MAA 本身带 beta 后缀时还会被整体 `scope-invalid` 拒绝。应按 MAA 支持的版本语义比较预发布版本，保留不能解析的版本为待核。

### R1-3 [P2] 标为 ready 的原始技能/精英组合可能被 Core 直接拒绝加载

位置：`skills/maa-core/scripts/stage-jobs.ts:52-58`（写原文处 `221-222`）。

合成账号拥有精二的六星干员能天使，作业 `skill: 3, requirements: { elite: -1, level: 40 }` 被探针判 ready。固定 MAA Core 对已识别干员计算 S3 的最低精英阶段 2，遇到显式 elite=-1（同样包括 0/1）直接返回解析失败。常规 GUI 导入会先提高这个要求；本工具绕开导入、原样写列表资产，而开始前列表验证只读关卡名，不会修正。因此“准备 complete”后用户点开始仍加载失败。需在报告/批准前规范化且绑定派生内容，或将该组合标为不能直接准备；不能只检查账号已经解锁 S3。

### R1-4 [P2] Markdown 隐藏了查询未穷尽的事实

位置：`skills/maa-core/scripts/stage-jobs.ts:181-195`。

`collectStageJobs` 达到三页上限仍有下一页时输出 `search.truncated=true`，但 `formatStageJobs` 完全不输出 search。公开 CLI 使用 `format: "markdown"` 时只返回 Markdown，调用方连页数和截断事实都收不到。探针返回 JSON 截断为 true，而 Markdown 仅显示“主作业候选：待核；备选候选：无”。这违反规格新增的“未穷尽明确标记”，可让用户把前 60 份无匹配误认为该关无可用候选。需在每关摘要中显示查询覆盖与截断状态。
