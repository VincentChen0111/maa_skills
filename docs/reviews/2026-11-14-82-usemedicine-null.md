改动在消耗谓词旁边，所以按安全相关审查。协调者选了 Issue 的修法 (a)：字段检查接受 null 的理智药开关，因为 MAA 里它的类型是 `bool?`，消耗谓词和读取摘要本来就把 null 当作开启。

审查方式：每轮一名新上下文的独立审查员。审查员用临时目录和假 MAA 进程复现，只读核对固定 MAA 源码，没有调用真实模型，也没有运行真实 MAA。共三轮，在维护者定的上限（「轮数上限3」）之内。

## 第一轮

结论：有条件通过，P1 0、P2 0、P3 1。审查员核对了：
- **消耗仍然拒绝。** 在两种开关状态下逐个写入入口复现：没有授权时，启用、开着时重排、定时和来自已批准报告的请求，都在访问进程之前被拒绝，文件不变。
- **其他检查没有放宽。** 其余字段检查和 doctor 恢复的整份比较都没有改。

- **读取摘要有说明。** `maa-daily` 的配置说明写明 `on` 为 null 时按开启处理。
- **源码支持修法 (a)。** 审查员另找到一处：MAA 每次全部任务完成后，把 null 开关改回 false（`ResetAllTemporaryVariable`）。可见 null 是 MAA「仅本次」开启的状态。
