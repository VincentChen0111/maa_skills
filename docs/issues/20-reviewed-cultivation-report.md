实施进度：已完成。

2026-11-13 交付：培养建议报告（14 的真实计算、18 的 NGA 引用、作业站只读证据）、两宿主共用的独立审查协议（一名审查员、一轮、只接受真实错误、改正列出改动）、用户明确跳过时的「未审查」标记，以及逐项批准；[独立审查](../reviews/2026-11-13-20-cultivation-report.md)三轮，没有未解决的 P1、P2，剩下的一条 P3 转 [Issue #54](https://github.com/VincentChen0111/maa_skills/issues/54)。[验证记录](../cultivation-report-verification.md)写明实际运行的检查和未验证项：真实宿主上发起审查、观察器接入运行器（随 28），以及新场景的真模型评测（留给 26）。

成本数字本身不能回答先培养谁。用户需要结合玩法优先级、账号事实和社区依据的可执行建议，同时能识别报告是否经过独立审查。

## 要交付的行为

maa-account 生成分步骤培养建议与花费，经过默认独立审查后交用户批准；用户明确跳过时生成标明未审查的报告。

## 规格依据

用户故事：20、21、23、24、25、26。涉及章节：账号快照与建议报告；五个 skill 和边界；资料来源。术语使用父规格关联的术语表。

## 验收条件

- [x] 读取账号快照和用户已表达的玩法优先级，给出培养顺序、每步材料/龙门币花费及库存能支持到哪一步；缺少关键偏好时说明假设或询问。
- [x] 使用 14 的真实计算结果，结合 18 的 NGA 资料及可用的公开作业站依据说明推荐原因；资料附作者、日期、来源、可信度，事实与推断分开。
- [x] 公开作业站证据采用只读入口；需要程序化匹配时复用共享工具，不另建重复实现。19 的森空岛社区/B 站结果可按同一资料格式补充，但缺少实验性来源不阻塞核心报告。
- [x] 对会交给 daily 执行的报告默认启动独立审查：一个审查员、只审一轮、只接受真正错误；记录每项接受/拒绝理由及结论。接受的错误改正后不再复审，报告列出这些改动。
- [x] 两个宿主共用自包含审查说明；Claude 使用新上下文，Codex 使用新 codex exec 进程；无法完成审查时如实标明，不能冒充已审查。
- [x] 用户当次明确跳过时不启动审查，报告醒目标明「未审查」；随口问答无需套用报告审查。
- [x] 报告中的建议条目可被用户逐项批准，并明确批准范围；审查通过不等于执行授权，account 不写 MAA 配置或执行培养。

## 验证方式

用合成快照、成本和资料走完整报告流程，检查逐步预算、来源、事实/推断、默认审查、明确跳过、未获批准不执行；真实宿主隔离评测验证独立审查发起方式。

## 依赖理由

14 提供加工和凭证后的可信缺口；18 提供一个可运行的社区证据来源。报告审查协议随后由 22 复用。

## 实现与交付约定

有代码行为的改动先写外部行为测试，使用真实临时目录，只替代 MAA 进程、adb 和网络；skill 改动按同模型、同场景做前后评测，真模型只在本机运行。每个改动包经一个独立审查员审查，最多三轮，记录意见处置和结论；公开前检查所有移植文件及合成样例的隐私，经分支、PR 和 squash 合并。

构建与评测使用临时 home，不改动维护者现有 MAA、已安装 skill 或私有生产环境。沿用本票所列规格决定；新增或修改限制时在规格两张来源表登记来源。
