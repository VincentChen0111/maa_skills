## 背景与目标

实施进度：未开始。

NGA、森空岛账号和实验性 B 站功能可能需要用户凭据。凭据输入应留在用户操作的本地脚本中。

## 要交付的行为

setup 给出用户手动配置凭据的入口，读取器和 doctor 可获得存在/过期状态，而对话和输出中不出现凭据值。

## 规格依据

用户故事：6、10、54。涉及章节：私有目录与设置文件；检查与修法；资料来源；安全边界。术语使用父规格关联的术语表。

## 验收条件

- [ ] 为 NGA、森空岛账号和 B 站提供用户直接运行并输入的流程；agent 不请求用户在对话中粘贴秘密，不代替登录。
- [ ] 凭据放在仓库外的用户私有位置，读取器内部按需要使用；设置文件和普通输出只携带定位/状态所需信息，不包含秘密值。
- [ ] 检查区分未设置、可用、已知过期及尚未验证；不能仅凭存在就声称有效，也不为检查打印 token、Cookie 或账号标识。
- [ ] 用户输入取消或失败不破坏已有可用设置；错误、日志与诊断输出保持脱敏。
- [ ] 明确 B 站功能为实验性。森空岛社区公开读取不复用森空岛账号凭据。
- [ ] setup 和 doctor 共用凭据检查，doctor 修复仍需点名批准；重新登录或重新输入属于用户手动修法。

## 验证方式

使用合成秘密标记及网络替身测试输入取消、存在/过期/未知状态和输出；扫描 stdout、stderr、普通记录确认无秘密，测试不读取维护者真实凭据。

## 依赖理由

07 提供 setup 引导、私有目录和检查/修法流程。

## 实现与交付约定

有代码行为的改动先写外部行为测试，使用真实临时目录，只替代 MAA 进程、adb 和网络；skill 改动按同模型、同场景做前后评测，真模型只在本机运行。每个改动包经一个独立审查员审查，最多三轮，记录意见处置和结论；公开前检查所有移植文件及合成样例的隐私，经分支、PR 和 squash 合并。

构建与评测使用临时 home，不改动维护者现有 MAA、已安装 skill 或私有生产环境。沿用本票所列规格决定；新增或修改限制时在规格两张来源表登记来源。
