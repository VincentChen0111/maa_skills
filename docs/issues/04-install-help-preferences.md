# 04: 可安装的 help 与偏好设置

Type: task
Labels: task

Assignee: unassigned

Blocked by: [03: 双宿主行为评测](03-cross-host-evaluation.md)

## 背景与目标

实施进度：未开始。

用户安装后的第一个入口应能解释该用哪个 skill，并把语言及私有目录设置保留下来。共享工具放在仓库中，并不自动保证按单个 skill 路径安装后还能调用。

## 要交付的行为

在两个宿主的原生安装结果中运行 maa-help，完成路由、语言偏好更新和偏好原话追加，贯通共享脚本的实际可达路径。

## 规格依据

用户故事：7、8、11、12、13、48、49、50、51、52、66。涉及章节：仓库与打包；五个 skill 和边界；私有目录与设置文件。术语使用父规格关联的术语表。

## 验收条件

- [ ] Claude 插件市场和 Codex skill-installer 按仓库路径安装后，maa-help 及其共享偏好脚本均可运行；共享工具仍只有一份源实现，无额外复制安装脚本。
- [ ] 设置文件记录语言、私有目录、MAA 目录与服务器；默认使用用户目录下的 .maa-skills，MAA_SKILLS_HOME 可切换到测试目录；只有偏好脚本通过临时文件再改名写入。
- [ ] 所有 skill 可复用启动时读取语言的入口；未设置时用当前用户的语言并提示可设置，setup 能判断是否已经问过语言。
- [ ] 用户说「以后用英文」后，下一次调用按设置回复；MAA 自身界面语言不变。偏好原话带日期与出处追加，旧条目保持原文。
- [ ] help 正确区分安装、账号建议、日常操作和诊断；缺少环境时引导 setup/doctor，尚未交付的 skill 如实说明，不声称已经可执行。
- [ ] help 的写入限于结构化设置和偏好原话；不创建或改写账号快照、建议报告、运行记录和 MAA 配置。
- [ ] 给出两种原生安装/更新和开发目录联接的可复现说明；只在临时宿主目录演示，不迁移维护者现有安装。

## 验证方式

测试原子替换及失败时旧设置保留、语言切换、追加记录和禁止越界写入；在两个临时宿主安装位置运行 help，并建立其行为基线。

## 依赖理由

03 提供两个宿主的隔离安装与行为验证能力。

## 实现与交付约定

有代码行为的改动先写外部行为测试，使用真实临时目录，只替代 MAA 进程、adb 和网络；skill 改动按同模型、同场景做前后评测，真模型只在本机运行。每个改动包经一个独立审查员审查，最多三轮，记录意见处置和结论；公开前检查所有移植文件及合成样例的隐私，经分支、PR 和 squash 合并。

构建与评测使用临时 home，不改动维护者现有 MAA、已安装 skill 或私有生产环境。沿用本票所列规格决定；新增或修改限制时在规格两张来源表登记来源。
