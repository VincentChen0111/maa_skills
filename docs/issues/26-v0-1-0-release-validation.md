## 要交付的行为

完成五个 skill 的发布验收，形成可复现的安装/更新、行为评测、版本核实及许可证据，按规格发布 v0.1.0。

## 规格依据

用户故事：11、12、13、59、62、63、65、66、69。涉及章节：发布与维护流程；仓库与打包；测试决定；隐私；致谢与免责。术语使用父规格关联的术语表。

## 验收条件

- [ ] 在两个临时宿主环境从实际发布内容原生安装和更新五个 skill，验证每个入口和共享脚本可达；开发目录联接也在临时位置验证。
- [ ] 验证 setup→account→用户批准→daily 及 help/doctor 的关键交接，所有 skill 读取语言，结构化设置与偏好原话及各自写入边界一致。
- [ ] 离线脚本测试、评分规则自检、隐私检查通过；维护者本机对各 skill 起步 3–6 个场景及已有回归场景运行同模型前后评测，pass→fail 按规则重跑三次。
- [ ] 核对全部已实现 MAA 依赖已登记；发布说明区分源码已核、实机已核和未验证，不将离线测试或历史经验算作实机通过。
- [ ] 版本从 v0.1.0 开始，语义化版本号、插件描述和更新记录同步；经分支、独立审查、PR 及 squash 合并后发布，main 保护保持。
- [ ] 逐文件检查公开内容与第三方声明，保留 MIT 全文、原版权行、借用提交号及致谢；不包含私人路径、账号数据、配置原文或打包游戏数据。
- [ ] 记录实际运行结果及未验证项；未执行的真实设备验证不记通过，若需要用户操作则明确跟踪到相应状态。
- [ ] 本票不迁移维护者个人数据、不更改现有日用 MAA 或已安装 skill；私有迁移及其他项目改为消费共享工具另行交办。

## 验证方式

使用干净安装、临时 home、合成账号和系统边界替身完成发布候选验收；真模型只在本机运行。保存检查命令、结果、版本和审查结论，核对最终标签与产物一致。

## 实现与交付约定

有代码行为的改动先写外部行为测试，使用真实临时目录，只替代 MAA 进程、adb 和网络；skill 改动按同模型、同场景做前后评测，真模型只在本机运行。每个改动包经一个独立审查员审查，最多三轮，记录意见处置和结论；公开前检查所有移植文件及合成样例的隐私，经分支、PR 和 squash 合并。

构建与评测使用临时 home，不改动维护者现有 MAA、已安装 skill 或私有生产环境。沿用本票所列规格决定；新增或修改限制时在规格两张来源表登记来源。
