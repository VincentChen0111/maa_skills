## 背景与目标

实施进度：未开始。

[05](05-daily-safe-config-write.md) 交付的写入脚本用 revision 指纹把写入请求绑定到用户批准时读到的配置。对照同类公开项目，有两处值得核对和加固：这个指纹会不会被 MAA 自己的写入打断，以及用户批准时看到的差异是否就是最后写进去的差异。

2026-11-13 新增本票。维护者当日同意把这批建议写进工单，说明见[工单索引](INDEX.md)；下面各条的具体写法是设计默认值，不是维护者原话，对应的行已登记在规格「默认值及其来源」。

当前实现，行号以基点 `05d4ebd` 的 `skills/maa-core/scripts/maa-config.ts` 为准，实现时按标识符重新定位：

- revision 是整份配置的指纹，不是投影：它对解析后的整份 `gui.new.json` 做 `JSON.stringify` 再取 SHA-256（第 27 行）。读取摘要返回它（第 410 行）；写入请求的 `expectedRevision` 和当前配置的 revision 不相等时，以 `configuration-changed` 拒绝（第 490–491 行，setup 专用入口在第 461 行）。所以从读取摘要到提交写入请求之间，配置里任何一个字段变了，包括 MAA 自己写的、和这次改动无关的字段，批准都会失效。
- 关停 MAA 之后不再比整份指纹，只重新绑定目标对象的快照（第 478–479、563 行），并在关停后的配置上重新计算这次改动（第 565 行）。
- 命令行只有 `read` 和 `write` 两个动作（第 435–436 行），写入请求的字段是 `host`、`expectedRevision`、`closedConfirmed`、`authorization`、`changes`（第 440 行）。没有预览动作；差异（`changedKeys`，第 209 行）在写入时才由脚本算出，随结果返回。作业计划和专精计划的改动必须等于已批准计划推出的改动（第 63、85 行）；普通的当次请求没有这样的核对，用户批准时看到的内容由 agent 转述，脚本不知道用户看到了什么。
- 写回时把解析后的整个对象重新序列化（第 582 行），先写临时文件再改名（第 580–585 行）；备份保留原字节（第 572–573 行）。也就是说，改动在键的层面是最小的，在字节层面是整份重写。
- doctor 的恢复比较用同一个整份指纹判断当前配置等于备份还是等于预期结果（第 313 行）。

## 要交付的行为

MAA 自己改动和本项目无关的运行时字段时，已批准的写入请求不因此失效；写入器读取或修改的字段有变化时仍然失效。普通的当次写入也能证明，写进去的差异就是用户批准时看到的差异。

## 验收条件

- [ ] 先核实问题是否存在：在固定 MAA 源码上列出，MAA 运行期间不经用户操作会自己写回 `gui.new.json` 的字段，以及写回的时机，结论和源码位置写进验证记录。如果核实结果是这段时间里 MAA 不会自己写这个文件，投影指纹这一部分不实施，在本票记下理由，只做后面的差异核对。
- [ ] 投影指纹：revision 改为对「投影」取指纹。投影包括写入器可以修改的字段，以及写入器做判断时读取的字段：安全谓词读取的消耗设置、任务身份字段、决定定时目标的当前配置、模式和队列，还有 setup 专用入口的连接字段。不在投影里的字段变化不使批准失效。投影的范围只在一处定义，读取摘要、写入核对和 setup 专用入口共用它。一个一致性测试枚举写入器白名单里的每一个字段，以及安全谓词读取的每一个字段，断言它们都在投影里；新增字段而没有进投影时这个测试失败。
- [ ] 业务字段漂移仍然拒绝：投影里任何一个字段在读取摘要之后变了，写入仍以 `configuration-changed` 拒绝，并且在访问进程、加锁和写入之前发生。关停后重新绑定目标快照（`authorized-target-changed`）的现有核对不变。
- [ ] 恢复比较不放宽：doctor 判断「当前配置等于备份」或「等于预期结果」时，仍然比较整份配置，不改用投影；规格「检查与修法」要求恢复只在精确一致时提供修法。恢复用的比较和写入用的 revision 分成两个名字清楚的函数。
- [ ] 差异核对：新增只读的预览动作，按请求算出这次写入会造成的差异：每个改动的键、改动前后的白名单摘要，以及一个差异指纹。预览不关停 MAA，不加锁，不写文件。写入请求带上用户批准时的差异指纹；写入器关停 MAA 之后在本机重新计算差异，指纹不相等就拒绝，配置字节不变，并给出能和 `configuration-changed` 区分的静态原因码。作业计划、专精计划和 setup 专用入口已有的「改动必须等于批准内容」的核对保留，不被差异指纹取代。
- [ ] 待执行记录和恢复：待执行记录保存差异指纹。恢复时不复用历史批准，现有规则不变。
- [ ] 不扩大改动范围：仍然只改必要的键，投影和差异核对都不成为多写字段的理由。现状是整份对象重新序列化后写回；本票核实这对没有改动的键是否无损，用含大整数、浮点写法、转义字符、非默认键顺序和不同行尾的合成配置做读回测试。无损就保持现状并留下测试。有损就改为不改变未触及键的值，改法和取舍写进验证记录。
- [ ] 读取摘要仍然只输出白名单内容；预览输出同样不含配置名、任务名、连接地址和完整配置。
- [ ] 文档和规格：`skills/maa-daily/references/configuration.md` 和相关 skill 正文写明预览、差异指纹和新的拒绝原因；规格「MAA 配置写入」里「读取摘要提供 revision 指纹，请求绑定该版本」和「revision 保留原始 JSON 的区别」两句，在交付时改成实际行为，规格两张来源表同步更新。
- [ ] 现有测试随规则更新，仍然成立的断言不删除；skill 改动按同一模型做前后评测。

参考，只对照思路，不复制代码：投影指纹和「确认的差异必须等于本机重算的差异」可参考 [yumi233/maa-control-center](https://github.com/yumi233/maa-control-center)（MIT）。

## 验证方式

先在写入脚本的命令行和导出函数接缝写失败测试，使用真实临时目录和假 MAA 进程。投影：只改投影外的字段后写入完成；改投影内的任一字段后被拒绝，拒绝发生在进程访问、加锁和写入之前。差异核对：预览后配置的目标字段变了，写入被拒绝，配置字节不变；预览和写入一致时写入完成并读回。恢复比较的现有测试保持通过。一致性测试单独运行并留存结果。MAA 自己写回哪些字段的核实只读源码，真实 MAA 上的验证没有做的如实记为未验证。

构建与评测使用临时 home，不改动维护者现有 MAA、已安装 skill 或私有生产环境。沿用本票所列规格决定；新增或修改限制时在规格两张来源表登记来源。
