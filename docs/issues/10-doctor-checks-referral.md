## 背景与目标

实施进度：未开始。

遗留锁只是故障的一类。用户描述症状后，需要得到覆盖本项目范围的检查结果，以及清楚的修复或转介路径。

## 要交付的行为

扩充 maa-doctor 的检查组，定位 skill 安装与使用问题；对 MAA 内部问题提供官方入口和脱敏摘要。

## 规格依据

用户故事：39、40、41、42、44、45、46、47、60。涉及章节：检查与修法；MAA 版本跟踪。术语使用父规格关联的术语表。

## 验收条件

- [ ] 覆盖安装、连接、配置、写入锁、凭据、私有文件、skill 版本/目录联接八类检查入口；各项都给出状态、原因、修法和执行者。
- [ ] 继续默认只读诊断、逐项批准修复，允许一次点名多项；调用 setup、偏好和配置的现有通道，不创建第二套写入逻辑。
- [ ] 按结构化连接信息、任务链错误和子任务错误判断失败；进程退出码为 0 不视为任务成功，证据不足明确标为未知。
- [ ] 识别失败、MAA 缺陷、模拟器兼容和游戏更新未适配等本项目范围外问题只转介，给出 MAA 官方文档/FAQ/issue 入口及脱敏日志摘要。
- [ ] 检查 skill 更新和已有 MAA 核实版本记录；未核实版本只提醒，核实列表不存在或为空时如实说明。25 负责自动更新核实记录和端到端新版本提醒。
- [ ] 所有检查组维持人读/JSON 输出、0/1/2 退出码和最近检查记录；凭据、账号标识、连接地址及完整配置不进入摘要。

## 验证方式

通过各组正常/提醒/错误样例和结构化回调反例检查诊断、退出码、脱敏及修法授权；明确区分可修和转介，验证不存在「退出 0 就成功」的误判。

## 依赖理由

09 提供凭据检查并经 07、06 带入共享检查库和授权修法流程；无需等待后续版本 Action。

## 实现与交付约定

有代码行为的改动先写外部行为测试，使用真实临时目录，只替代 MAA 进程、adb 和网络；skill 改动按同模型、同场景做前后评测，真模型只在本机运行。每个改动包经一个独立审查员审查，最多三轮，记录意见处置和结论；公开前检查所有移植文件及合成样例的隐私，经分支、PR 和 squash 合并。

构建与评测使用临时 home，不改动维护者现有 MAA、已安装 skill 或私有生产环境。沿用本票所列规格决定；新增或修改限制时在规格两张来源表登记来源。
