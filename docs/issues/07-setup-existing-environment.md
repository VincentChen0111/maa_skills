maa-setup 每次现场检查现有环境，完成设置、私有目录骨架和连接测试，必要时安全修改连接设置。

## 规格依据

## 验收条件

- [ ] 按安装顺序检查 Windows 图形界面版 MAA、国服、Node 24、设置和私有目录；每次重新读取现状，通过的步骤跳过。
- [ ] 首次询问偏好语言和私有目录，已有设置不重复提问；通过偏好脚本写结构化设置，setup 只写私有目录骨架及环境记录。
- [ ] 发现现有 adb 和模拟器连接候选并测试连接，无法确定时明确需要用户选择；不通过 adb 点击或操作游戏。
- [ ] 连接类 MAA 设置经统一写入脚本修改；MAA 已关闭且无锁时仍先确认用户未操作，安装请求不能隐式绕过这个条件。
- [ ] 用户发起安装表示同意本票的安装步骤；缺失程序说明官方下载途径并交由 08 的下载流程，不自行下载。
- [ ] 读取已有验证版本记录，未核实的 MAA 版本只提醒不拒绝；不把起点 skill 的历史经验登记为本仓库的实机验证。
- [ ] 重复运行不破坏已完成设置；不写账号快照或建议报告。

## 验证方式

使用临时目录与 adb/MAA 边界替身覆盖完整、缺项、错误 Node、连接失败、MAA 关闭及再次运行；新增 setup 行为基线，检查语言和写入边界。

## 依赖理由

06 提供可复用的检查/修法和配置恢复路径，间接依赖统一配置写入。

## 实现与交付约定

有代码行为的改动先写外部行为测试，使用真实临时目录，只替代 MAA 进程、adb 和网络；skill 改动按同模型、同场景做前后评测，真模型只在本机运行。每个改动包经一个独立审查员审查，最多三轮，记录意见处置和结论；公开前检查所有移植文件及合成样例的隐私，经分支、PR 和 squash 合并。

构建与评测使用临时 home，不改动维护者现有 MAA、已安装 skill 或私有生产环境。沿用本票所列规格决定；新增或修改限制时在规格两张来源表登记来源。
