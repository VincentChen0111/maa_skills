用户明确交办一项日常队列、提醒或定时设置后，maa-daily 经统一写入脚本完成修改并给出白名单读回结果。

## 验收条件

- [ ] 移植起点 maa-daily 的通用配置流程并剥离个人内容；只执行用户当次明确的请求或已批准报告条目，保留待执行及运行记录。
- [ ] 同一脚本进程依次确认可写、独占获取锁、关闭 MAA、备份、最小修改、重开、读回、记录变更键、释放锁；锁记录 skill、宿主、PID、开始时间和步骤。
- [ ] 两个并发调用最多一个进入写入；活跃锁不被夺取，持有者消失时保留结果未知的证据并交给核对流程，不自动删锁重试。
- [ ] MAA 已关闭且无锁时先告诉用户，明确确认其未操作后才写；从关停到重开完成的整个区间避开定时触发前两分钟起的窗口。
- [ ] 验证 MAA 进程树已退出才写配置；慢退出、拒绝退出、备份/重启/读回失败均报告实际阶段，不把部分执行报告成成功。
- [ ] 拒绝打开源石、抽卡、礼包、付费、登录相关设置，偏好不能解除；理智药仅接受当次授权数量。
- [ ] 只输出允许的配置摘要和变更键，不泄露连接地址、凭据、账号标识或完整配置；无关配置值保留。

## 验证方式

先写 CLI 集成测试，使用真实临时目录及快/慢/拒绝退出的假 MAA 进程；覆盖并发、定时窗口、失败中断、禁止字段和合成秘密标记。添加 daily 两宿主行为场景。

## 实现与交付约定

有代码行为的改动先写外部行为测试，使用真实临时目录，只替代 MAA 进程、adb 和网络；skill 改动按同模型、同场景做前后评测，真模型只在本机运行。每个改动包经一个独立审查员审查，最多三轮，记录意见处置和结论；公开前检查所有移植文件及合成样例的隐私，经分支、PR 和 squash 合并。

构建与评测使用临时 home，不改动维护者现有 MAA、已安装 skill 或私有生产环境。沿用本票所列规格决定；新增或修改限制时在规格两张来源表登记来源。
