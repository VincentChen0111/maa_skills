## 背景与目标

实施进度：未开始。

基建排班前需要知道账号实际持有哪些干员，以及当前精英阶段解锁了哪些基建技能。简单按技能文字中的百分比排序无法代表完整收益。

## 要交付的行为

通过共享 CLI 按干员名或房间查询已持有干员的有效基建技能，输出条件和未核实部分。

## 规格依据

用户故事：22。涉及章节：共享工具；资料来源；账号快照与建议报告。术语使用父规格关联的术语表。

## 验收条件

- [ ] 从注明出处和固定提交的游戏数据生成基建技能表，运行时获取、不打包数据；移植通用逻辑时剥离个人路径、名册和生产环境依赖。
- [ ] 接收 11 的账号快照，按持有情况和实际精英阶段判断技能是否已解锁；未知练度保持待核，不假设为最高练度。
- [ ] 支持按干员名、房间类型查询，CLI 和 Markdown 列出当前生效技能、后续解锁技能及生效条件。
- [ ] 阵营组合、全局效果、心情或条件未建模时明确说明，不把文本中的首个百分比直接宣称为最终收益。
- [ ] KayChung17/arknights-base-skill 数据只用于交叉核对，差异报告给用户；引用与借用许可记录完整。
- [ ] 仅查询或生成供建议使用的数据，不写 MAA 配置、不安排干员、不改变账号快照事实。

## 验证方式

通过合成干员、技能、房间和练度数据检查解锁阈值、同名歧义、缺字段及条件效果；演示 CLI 到 Markdown 的结果，并测试交叉核对差异。

## 依赖理由

11 提供名册、练度和基建事实的统一输入。

## 实现与交付约定

有代码行为的改动先写外部行为测试，使用真实临时目录，只替代 MAA 进程、adb 和网络；skill 改动按同模型、同场景做前后评测，真模型只在本机运行。每个改动包经一个独立审查员审查，最多三轮，记录意见处置和结论；公开前检查所有移植文件及合成样例的隐私，经分支、PR 和 squash 合并。

构建与评测使用临时 home，不改动维护者现有 MAA、已安装 skill 或私有生产环境。沿用本票所列规格决定；新增或修改限制时在规格两张来源表登记来源。
