## 背景与目标

实施进度：未开始。

现有私人排班生成器带有个人布局和人员安排。公开用户需要基于自己的布局、名册和目标生成可校验的建议。

## 要交付的行为

maa-account 生成基建建议报告和可交给 daily 的自定义排班，说明收益依据并完成独立审查。

## 规格依据

用户故事：22、23、24、25、26。涉及章节：共享工具；账号快照与建议报告；五个 skill 和边界。术语使用父规格关联的术语表。

## 验收条件

- [ ] 从用户快照中的布局、持有干员和有效技能生成排班建议；移除特定用户的布局和人员硬编码，不把某个用户的安排当通用默认值。
- [ ] 至少校验房间容量、计划数上限、同计划不重复干员、键名大小写及 MAA 不能切换生产线；出现未持有干员给出警告。
- [ ] 容量、计划数等值来自实际支持的 MAA 版本及核实证据；新增限制或默认值登记到规格两张来源表，不凭经验编造上限。
- [ ] 报告说明每项收益的计算依据、条件和未建模部分，已核实与推断分开，列出用户可执行步骤及相关成本。
- [ ] 复用 20 的建议报告与独立审查流程；用户明确跳过时标「未审查」，审查通过仍需用户批准才能应用。
- [ ] 共享排班生成/检查提供 CLI 和 Markdown 输出，产物放在私有目录；account 不写入 MAA 配置。
- [ ] 借鉴外部排班规则时记录来源提交与许可；数据用时获取、样例合成，不携带原个人排班。

## 验证方式

用不同合成布局和名册验证有效排班、超容量、计划超限、同计划重复、大小写错误、生产线不支持及未持有警告；验证报告审查和预算结果。

## 依赖理由

21 提供实际生效技能；20 提供可复用的建议报告、用户批准条目及独立审查协议。

## 实现与交付约定

有代码行为的改动先写外部行为测试，使用真实临时目录，只替代 MAA 进程、adb 和网络；skill 改动按同模型、同场景做前后评测，真模型只在本机运行。每个改动包经一个独立审查员审查，最多三轮，记录意见处置和结论；公开前检查所有移植文件及合成样例的隐私，经分支、PR 和 squash 合并。

构建与评测使用临时 home，不改动维护者现有 MAA、已安装 skill 或私有生产环境。沿用本票所列规格决定；新增或修改限制时在规格两张来源表登记来源。
