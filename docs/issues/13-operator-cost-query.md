## 要交付的行为

通过命令行按干员名查询精英化、专精和模组目标，从当前练度算出材料与龙门币明细及 Markdown 结果。

## 规格依据

用户故事：17、25、26。涉及章节：共享工具；资料来源；账号快照与建议报告。术语使用父规格关联的术语表。

## 验收条件

- [ ] 移植成本计算及其数据构建的通用实现，解除原私有项目存储/运行环境耦合；逐文件检查代码、注释和样例，替换真实账号基线。
- [ ] 读取 11 的快照与明确目标，按名称找到干员；当前练度或目标不完整时标出待核输入，不当成零成本或已满足。
- [ ] 覆盖精英化、专精各级及模组各级的逐步材料和龙门币成本，总计可追溯到步骤；CLI 与 Markdown 表达同一结果。
- [ ] 运行时从明确注明的公开游戏数据镜像固定提交取数，不打包游戏数据；一图流材料价值和企鹅物流掉率按需读取并署名，不打包其数据。
- [ ] 提供原始成本及不加工的查询方式；加工与材料凭证的缺口决策由 14 补齐，本票不假称已经扣除。
- [ ] arkntools 只交叉核对成本，差异列出而不自动修正；数据来源、版本和不确定项出现在结果中。
- [ ] 共享计算仅保留一份可被 CLI 和其他项目引用的实现，不修改原私有项目的生产副本。

## 验证方式

用合成数据和网络样例先测逐级差分、当前等于目标、缺字段、名称歧义与来源冲突；实际执行 CLI 检查数值和 Markdown，测试不取真实游戏数据或账号。

## 依赖理由

11 提供带来源与未知值语义的快照输入，避免各工具另造账号格式。

## 实现与交付约定

有代码行为的改动先写外部行为测试，使用真实临时目录，只替代 MAA 进程、adb 和网络；skill 改动按同模型、同场景做前后评测，真模型只在本机运行。每个改动包经一个独立审查员审查，最多三轮，记录意见处置和结论；公开前检查所有移植文件及合成样例的隐私，经分支、PR 和 squash 合并。

构建与评测使用临时 home，不改动维护者现有 MAA、已安装 skill 或私有生产环境。沿用本票所列规格决定；新增或修改限制时在规格两张来源表登记来源。
