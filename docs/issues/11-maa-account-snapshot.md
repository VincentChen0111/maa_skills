## 背景与目标

实施进度：未开始。

账号分析需要可复用的事实输入，不能把识别缺失、未读取字段或旧数据误当成确定的零值。

## 要交付的行为

maa-account 引导用户在 MAA 启动仓库和干员识别，读取结果并生成共享工具可直接使用的账号快照。

## 规格依据

用户故事：14、16。涉及章节：账号快照与建议报告；共享工具；其他说明。术语使用父规格关联的术语表。

## 验收条件

- [ ] 识别由用户在 MAA 界面启动，skill 读取结果；不自行操作设备、不编写新的图像识别，也不改写 MAA 配置。
- [ ] 快照使用共享工具的输入格式，包含来源、读取时间，以及实际可获得的干员练度、仓库、龙门币和基建事实；不可得或不完整字段明确标注，不编造。
- [ ] 记录识别尚未完成、解析失败及字段缺失；未知练度不当作满足要求，未识别库存不无依据地填零。
- [ ] 若改写 dsh-maa-cli 的 Depot/OperBox 回调解析，先在固定提交逐字检查原代码，记录许可、原版权及来源；测试资料全部合成。
- [ ] maa-account 只写账号快照和报告，语言和偏好通过共用入口；快照保存在私有目录，不把账号标识或完整回调秘密输出到对话。
- [ ] 提供可离线导入样例识别结果的命令行演示和 Markdown 摘要，后续成本、作业和基建工具可直接消费。

## 验证方式

使用合成的完成/未完成/损坏/部分识别结果，检查输入格式、时间来源、未知值和脱敏；两宿主评测验证用户启动识别和 account 写入边界。

## 依赖理由

04 提供私有目录、设置和共享脚本入口；不依赖 setup 已完成，用户可已有配置好的 MAA。

## 实现与交付约定

有代码行为的改动先写外部行为测试，使用真实临时目录，只替代 MAA 进程、adb 和网络；skill 改动按同模型、同场景做前后评测，真模型只在本机运行。每个改动包经一个独立审查员审查，最多三轮，记录意见处置和结论；公开前检查所有移植文件及合成样例的隐私，经分支、PR 和 squash 合并。

构建与评测使用临时 home，不改动维护者现有 MAA、已安装 skill 或私有生产环境。沿用本票所列规格决定；新增或修改限制时在规格两张来源表登记来源。
