## 背景与目标

实施进度：未开始。

原评分逻辑可借鉴，但原驱动绑定其他运行环境。本项目需要面向 Codex 与 Claude Code 的统一行为证据。

## 要交付的行为

用同一组场景在两个宿主的隔离环境中运行 skill，记录外部行为、评分并比较前后版本。

## 规格依据

用户故事：62、63。涉及章节：测试决定；账号快照与建议报告。术语使用父规格关联的术语表。

## 验收条件

- [ ] 复用可独立使用的评分与匹配思路，移植前检查全部内容的隐私与许可；驱动使用 codex exec 和 claude -p，不要求原私有项目或其生产环境。
- [ ] 每次运行建立真实临时 home、私有目录、MAA 样例和合成账号数据；只替代 MAA 进程、adb 和网络边界，正常用户安装与真实配置不受影响。
- [ ] 把两个宿主记录转换成共同格式，评分只依据动作、脚本调用、文件变化和授权证据，不按回复措辞评分；提供一个可端到端演示的隔离场景。
- [ ] 每条评分规则都带应通过/应拦截记录，覆盖授权、写入锁、允许键、禁止设置、秘密输出、下载确认和报告审查标记；自检可完全离线。
- [ ] 比较前后版本时固定模型和场景，保留版本、宿主及运行证据；pass→fail 的场景单独重跑三次后再判断，失败或未运行不记为通过。
- [ ] 支持后续每个 skill 添加起步 3–6 个场景，数量不是上限；新 skill 建立基线，已有 skill 修改后的分数不得下降。
- [ ] 验证独立 Codex 审查可由新进程和自包含 brief 启动，Claude 使用新上下文；不能运行的宿主明确记为未验证，不伪造双宿主结果。

## 验证方式

先用样例记录测试归一化、评分和回归判定，再在维护者本机跑两种宿主的最小隔离场景；CI 只运行离线部分，记录真模型实际运行与未验证项。

## 依赖理由

02 提供离线运行入口、隐私检查和审查证据约定。

## 实现与交付约定

有代码行为的改动先写外部行为测试，使用真实临时目录，只替代 MAA 进程、adb 和网络；skill 改动按同模型、同场景做前后评测，真模型只在本机运行。每个改动包经一个独立审查员审查，最多三轮，记录意见处置和结论；公开前检查所有移植文件及合成样例的隐私，经分支、PR 和 squash 合并。

构建与评测使用临时 home，不改动维护者现有 MAA、已安装 skill 或私有生产环境。沿用本票所列规格决定；新增或修改限制时在规格两张来源表登记来源。
