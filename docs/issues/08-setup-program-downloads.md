## 背景与目标

实施进度：已完成。

2026-11-14 交付：MAA、模拟器、adb、Node 缺失时，setup 给出下载方案（文件名、版本及出处、官方来源、大小、校验值）。下载有几条约束：
- 用户确认后只从官方来源下载并校验；
- 每份方案用一次，与指纹绑定；
- MAA 和 adb 只解压到用户所选的空文件夹；
- 模拟器只按一张厂商表判断官方主机，任何一跳返回 401／403 都记为 `source-refused`，不重试，不伪造请求头；
- 蓝叠 5（国内版）由用户自己下载，维护者 2026-11-14 确认。

[独立审查](../reviews/2026-11-13-08-setup-downloads.md)共五轮（维护者 2026-11-14 同意本次任务可以超过三轮），没有未解决的 P1、P2，剩下的一条 P3 转 [Issue #67](https://github.com/VincentChen0111/maa_skills/issues/67)。[验证记录](../setup-verification.md)写明实际运行的检查和未验证项：
- 真实安装包的内容；
- 厂商以后更换主机；
- 真模型前后评测（留给 26）。

环境缺项时 setup 需要把检查结果推进到可用环境，但每次程序下载都由用户决定。

## 要交付的行为

setup 展示缺失程序的官方下载方案，获得本次确认后下载并指导或完成允许的安装步骤，最后重新检查。

## 规格依据

用户故事：1、2、3、4。涉及章节：仓库与打包；检查与修法；安全边界。术语使用父规格关联的术语表。

## 验收条件

- [x] 支持 MAA、模拟器、adb 和 Node 的缺项流程；给出明确文件名、版本、官方来源与大小，无法取得大小时如实说明。
- [x] 每次程序下载都先向用户展示方案并取得确认；拒绝后不发起下载，不借之前的安装请求或旧授权自动放行。
- [x] 程序来自官方来源，记录具体选择的版本与出处；测试使用下载样例，不访问真实发行包。
- [x] 区分 skill 可执行与必须用户操作的安装步骤；用户手动完成登录或界面步骤，skill 不输入游戏账号或操作设备。
- [x] 下载失败、中断或安装未完成时不标成已安装；恢复调用先检查现状，通过的步骤不重复。
- [x] 完成后重新检查 Node、MAA、adb 与连接，更新环境记录；设置和 MAA 配置仍通过各自已有写入通道。

## 验证方式

网络替身覆盖同意/拒绝、来源异常、大小未知、下载中断及安装后复检；行为评测断言下载发生在明确确认之后，未通过检查时不假报完成。

## 依赖理由

07 提供环境检查、安装顺序和复检结果。

## 实现与交付约定

有代码行为的改动先写外部行为测试，使用真实临时目录，只替代 MAA 进程、adb 和网络；skill 改动按同模型、同场景做前后评测，真模型只在本机运行。每个改动包经一个独立审查员审查，最多三轮，记录意见处置和结论；公开前检查所有移植文件及合成样例的隐私，经分支、PR 和 squash 合并。

构建与评测使用临时 home，不改动维护者现有 MAA、已安装 skill 或私有生产环境。沿用本票所列规格决定；新增或修改限制时在规格两张来源表登记来源。
