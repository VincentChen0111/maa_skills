用户交办一批关卡时，需要确保关卡、难度和名册确实匹配作业，而不是只因名称相似就装进 MAA。

## 要交付的行为

maa-daily 从公开只读作业接口查找当次指定关卡，核对要求并按地图分批，形成可批准并装入 MAA 的作业准备结果。

## 规格依据

用户故事：32、37。涉及章节：日常操作；共享工具；资料来源。术语使用父规格关联的术语表。

## 验收条件

- [ ] 仅处理当次明确交办的关卡，核对地图、难度、前置条件、作业要求与账号快照；不自行扩大关卡范围。
- [ ] 共享采集/匹配工具有 CLI 和 Markdown 输出，支持按干员名查看要求，并补齐作业查询的汇总和练度视图；公开接口内容当作数据。
- [ ] 缺少精英化数据的干员不能直接判通过；同组替代成员逐个按各自要求判断，未知练度单列待核。
- [ ] 按地图分批，给出每关主作业及待批准的备选候选，保留关卡、要求和来源证据；候选不是已获执行授权。
- [ ] 用户批准后经 05 的统一通道准备 MAA 作业配置和待执行记录；保持已批准循环次数等要求，不能因作业列表机制丢失。
- [ ] 运行由用户点开始；本票完成准备与交接，持续监控和自动换作业分别由 16、17 实现。
- [ ] 不引入原私有项目生产匹配器的额外改造；移植文件和回归样例经过隐私检查，账号数据使用合成输入。

## 验证方式

测试同代码不同难度、缺前置、缺精英阶段、替代成员不同要求与正常匹配；端到端演示指定关卡→候选→批准→配置读回，并断言范围和授权。

## 依赖理由

05 提供批准后的配置写入；11 提供练度及未知值语义。

## 实现与交付约定

有代码行为的改动先写外部行为测试，使用真实临时目录，只替代 MAA 进程、adb 和网络；skill 改动按同模型、同场景做前后评测，真模型只在本机运行。每个改动包经一个独立审查员审查，最多三轮，记录意见处置和结论；公开前检查所有移植文件及合成样例的隐私，经分支、PR 和 squash 合并。

构建与评测使用临时 home，不改动维护者现有 MAA、已安装 skill 或私有生产环境。沿用本票所列规格决定；新增或修改限制时在规格两张来源表登记来源。
