# 17: 批准范围内切换备选作业

Labels: task

Assignee: unassigned

## 背景与目标

实施进度：未开始。

主作业明确失败时，用户希望沿用事前批准的候选继续；结果未知或备选用完时不能继续试探。

## 要交付的行为

maa-daily 在明确失败或未三星后，按批准顺序切换同一关卡的下一份备选并跟踪结果。

## 规格依据

用户故事：33、34、35、38。涉及章节：日常操作；安全边界；默认值及其来源。术语使用父规格关联的术语表。

## 验收条件

- [ ] 准备时每关主作业和备选一起交用户批准；备选默认最多列三份，用户批准时可增减，未批准候选不进入可执行队列。
- [ ] 仅当前关卡明确失败或未三星触发切换；结果未知、理智不足和证据不足不被当成换作业理由。
- [ ] 逐份消费批准的备选，成功后进入已批准批次的后续流程，备选用尽停止并报告；不临时搜索未经批准的作业自动继续。
- [ ] 备选配置仍通过统一写入通道，保留循环次数等已批准参数；药剂数量严格限于当次授权，不因重试增加。
- [ ] 在固定 MAA 版本上核实可用的原生续跑机制并记录依赖；可用时由 MAA 自行启动，不可用时准备好备选并明确请用户点开始。
- [ ] 中断恢复先核对运行及候选使用记录，不重复已执行候选；每次切换原因、候选和结果可追溯。
- [ ] 不采用直接操作设备或未批准的自动换作业机制。

## 验证方式

用结构化回调与假 MAA 验证失败→备选→成功、未三星、候选用尽、未知结果、无理智和恢复场景；续跑方式分别验证原生可用和用户交接路径。

## 依赖理由

16 提供关卡身份、确定终态及未知状态；经它复用作业准备和统一写入。

## 实现与交付约定

有代码行为的改动先写外部行为测试，使用真实临时目录，只替代 MAA 进程、adb 和网络；skill 改动按同模型、同场景做前后评测，真模型只在本机运行。每个改动包经一个独立审查员审查，最多三轮，记录意见处置和结论；公开前检查所有移植文件及合成样例的隐私，经分支、PR 和 squash 合并。

构建与评测使用临时 home，不改动维护者现有 MAA、已安装 skill 或私有生产环境。沿用本票所列规格决定；新增或修改限制时在规格两张来源表登记来源。
