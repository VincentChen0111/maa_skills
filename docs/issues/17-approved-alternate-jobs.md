## 要交付的行为

maa-daily 在明确失败或未三星后，按批准顺序切换同一关卡的下一份备选并跟踪结果。

## 规格依据

用户故事：33、34、35、38。涉及章节：日常操作；安全边界；默认值及其来源。术语使用父规格关联的术语表。

## 验收条件

- [ ] 准备时每关主作业和备选一起交用户批准；备选默认最多列三份，用户批准时可增减，未批准候选不进入可执行队列。
- [ ] 仅当前关卡明确失败或未三星触发切换；结果未知、理智不足和证据不足不被当成换作业理由。环境类失败不算当前作业失败：不自动切换，这份作业不记为已用；16 查明原因后，模型可以决定重试这一份或换下一份已批准的备选，并记录理由。
- [ ] 逐份消费批准的备选，成功后进入已批准批次的后续流程，备选用尽停止并报告；不临时搜索未经批准的作业自动继续。
- [ ] 备选配置仍通过统一写入通道，保留循环次数等已批准参数；理智药和碎石的数量严格限于当次授权，不因重试或换作业增加，临期药只在当次已批准时沿用。2026-11-13 补充：上一次运行（失败或被中断）已经用掉的数量算在同一次批准里；换备选或重试只能用剩下的数量，开始之前经统一写入通道把配置里的数量改成剩余数，否则要用户重新批准。用掉多少查不清时停下告诉用户，不重试，也不换下一份。碎石和临期药由 [27](27-approved-stone-expiring-medicine.md) 交付，27 完成之前不可用。
- [ ] 在固定 MAA 版本上核实可用的原生续跑机制并记录依赖；可用时由 MAA 自行启动，不可用时准备好备选并明确请用户点开始。
- [ ] 中断恢复先核对运行及候选使用记录，不重复已执行候选；每次切换原因、候选和结果可追溯。恢复之前重新读取状态，不假设理智、药剂、源石或关卡进度和批准时相同，因为用户可能手动玩过。
- [ ] 不采用直接操作设备或未批准的自动换作业机制。
- [ ] 运行和候选使用记录是一个写明的状态机，状态和允许的转移写进验证记录。宿主、脚本进程或 MAA 重启之后，记录里仍处于进行中的运行改记为「已中断」，按结果未知核对（第 6 条），不自动接着跑。用户重新批准或点开始的是一次新的运行，带新的标识，旧记录保留。
- [ ] 每次切换请求带一个幂等键，键的构成在实现时定，至少能区分批次、关卡和候选。同一个键重复提交、输入也相同时，返回已有的记录，不再执行一次；同一个键而输入不同时拒绝，两份输入的摘要都留作证据，转核对。
- [ ] 2026-11-13 新增：交付时更新 `CONTEXT.md` 的「备选作业」条目，使它和规格「检查与修法」的环境类失败规则一致。

参考，只对照思路，不复制代码：环境类失败不换作业、只有作业本身失败才换，可参考 [nhyo/dsh-maa-cli](https://github.com/nhyo/dsh-maa-cli)（MIT）；它未经批准自动换作业的做法不借鉴，见规格「其他说明」。运行状态机和幂等键可参考 [mps233/La-pluma](https://github.com/mps233/La-pluma) 及其分叉 [dongwlin/La-pluma-next](https://github.com/dongwlin/La-pluma-next)（均 MIT）。

## 验证方式

用结构化回调与假 MAA 验证失败→备选→成功、未三星、候选用尽、未知结果、无理智、环境类失败（不切换、作业不记为已用）和恢复场景；续跑方式分别验证原生可用和用户交接路径。2026-11-13 补充：验证重启后进行中的运行变为已中断且没有被接着执行，同一幂等键相同输入只执行一次，同一幂等键不同输入被拒绝并留下证据。另回放「批准 N 瓶理智药，用掉 N 瓶之后被中断」的样例：重试或换备选不能再按 N 开始，配置里的数量先改成剩余数；剩余为 0 或用掉多少未知时停下。

## 依赖理由

16 提供关卡身份、确定终态及未知状态；经它复用作业准备和统一写入。

有代码行为的改动先写外部行为测试，使用真实临时目录，只替代 MAA 进程、adb 和网络；skill 改动按同模型、同场景做前后评测，真模型只在本机运行。每个改动包经一个独立审查员审查，最多三轮，记录意见处置和结论；公开前检查所有移植文件及合成样例的隐私，经分支、PR 和 squash 合并。

构建与评测使用临时 home，不改动维护者现有 MAA、已安装 skill 或私有生产环境。沿用本票所列规格决定；新增或修改限制时在规格两张来源表登记来源。
