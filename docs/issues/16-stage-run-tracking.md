## 背景与目标

实施进度：未开始。

MAA 进程退出成功并不等于关卡成功。中途断连和日志不完整时，重复运行可能造成重复消耗。

2026-11-13 按维护者当日的决定修订验收第 1、2、4 条并新增第 5 条：环境类失败先查明原因再由模型决定，用户手动玩要考虑进去，来源见规格「默认值及其来源」。

## 要交付的行为

用户启动已准备批次后，maa-daily 持续跟踪结构化回调，保存运行记录并明确报告每关终态或需要核对的未知状态。

## 规格依据

用户故事：32、33、34、35。涉及章节：日常操作；检查与修法；安全边界。术语使用父规格关联的术语表。

## 验收条件

- [ ] 关联准备批次、关卡和本次运行，持续跟踪至成功、失败、未三星、理智不足、明确超时、环境类失败或结果未知的交接状态。
- [ ] 依据连接、任务链和子任务的结构化回调分类，不只靠关键词；进程退出码 0 不覆盖回调中的失败。环境类失败（连接、模拟器或游戏客户端、MAA 进程、识别环境）和作业失败分开，不记为该关失败。
- [ ] 及时报告失败、未三星、理智不足和明确超时，运行记录带对应证据；不把沉默或短暂没有新日志自动当作失败。
- [ ] 断连、进程中断等环境类失败先查明原因并核对当前状态；状态核对清楚后由模型决定：在原批准范围内重试、换下一份已批准的备选（经 17），或者停下告诉用户，并记录理由。重试不增加理智药或碎石的授权数量，启动方式不变（用户点开始，或 MAA 自己的机制）。结果仍然未知或证据不全时只核对，不重新启动、重打或换作业。
- [ ] 能从回调或用户的说明看出用户正在手动玩（模拟器或官方 PC 客户端）、或者手动登录把 MAA 的会话顶下线时，按环境类失败处理，不记为作业失败；继续之前重新读取状态，不沿用批准时的理智、药剂、源石或关卡进度，读不到的标为未知。
- [ ] 复用共享诊断分类并向用户给出下一步；日志摘要、运行记录和输出不含凭据、账号标识或完整配置。
- [ ] 在临时环境中完整演示从用户开始信号到运行结果的跟踪，不点击游戏或操作设备。

## 验证方式

回放正常、失败、未三星、无理智、超时、断连、手动会话顶下线及退出 0 但失败的合成结构化事件；验证不会重复执行或误报成功，环境类失败不记为该关失败，添加两宿主行为场景。

## 依赖理由

15 提供明确批次和已准备作业；06 提供共享诊断结果与结果未知的核对接口。

## 实现与交付约定

有代码行为的改动先写外部行为测试，使用真实临时目录，只替代 MAA 进程、adb 和网络；skill 改动按同模型、同场景做前后评测，真模型只在本机运行。每个改动包经一个独立审查员审查，最多三轮，记录意见处置和结论；公开前检查所有移植文件及合成样例的隐私，经分支、PR 和 squash 合并。

构建与评测使用临时 home，不改动维护者现有 MAA、已安装 skill 或私有生产环境。沿用本票所列规格决定；新增或修改限制时在规格两张来源表登记来源。
