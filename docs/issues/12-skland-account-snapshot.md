## 背景与目标

实施进度：进行中。

不开模拟器时，森空岛可作为第二种账号事实来源。它必须产生与 MAA 识别兼容、来源清楚的快照。

2026-11-13 补充：参考同类公开项目，新增验收第 7–12 条、「待实现时核对的接口与字段」表和「参考」一段，写的是字段核对、格式转换和要让用户知情的事项，不新增产品限制；凭据只走 token 的限制在 [09](09-manual-credentials.md)。维护者当日同意把这批建议写进工单，说明见[工单索引](INDEX.md)；各条的具体写法是设计默认值，不是维护者原话。表里的接口和字段都还没有在本仓库核对。

## 要交付的行为

maa-account 使用用户已配置的凭据只读取得账号数据，保存统一账号快照并报告读取状态。

## 规格依据

用户故事：15、16。涉及章节：账号快照与建议报告；资料来源；安全边界。术语使用父规格关联的术语表。

## 验收条件

- [ ] 使用 09 的凭据入口和 11 的快照格式；用户无需启动模拟器，agent 不代替账号登录。
- [ ] 请求只用于读取账号数据，不执行签到、发帖、点赞、付费或其他账号写操作；只读约束沿用 01 更正后的设计来源。
- [ ] 输出覆盖实际可取得的干员、仓库、龙门币和基建字段，带读取时间及森空岛来源；缺失字段仍为未知。
- [ ] 凭据缺失、过期、网络失败或响应不完整时给出可行动状态，不伪造新快照成功或悄悄把旧数据当成本次数据。
- [ ] MAA 与森空岛来源可区分；并列数据发生冲突时展示差异和时间，不静默拼成无法追溯的事实。
- [ ] 秘密及账号标识不进入对话、Markdown 或错误日志；账号快照留在私有目录，MAA 配置不变。
- [ ] 森空岛的接口和字段逐项核对之后，才写进读取器和来源记录。下面「待实现时核对的接口与字段」表是核对的起点，不是已核事实；核对结果和表不同时按实际情况写，并在来源记录里说明。
- [ ] 转成统一账号快照时处理两处差一：快照的 `rarity` 和 `potential` 都是 1–6（见 `skills/maa-core/scripts/account-snapshot.ts`），森空岛的稀有度和潜能从 0 计数时各加 1。两处各有测试，用合成响应断言转换后的值。实现时先核对森空岛这两个字段从几开始计数。
- [ ] 技能等级、专精和模组能从森空岛取得时写进快照并标明来源，补上 MAA 干员识别给不出的部分（11 导入的快照里这三项为空）；取不到的保持未知。
- [ ] 没有找到来源的三类事实，在快照里明确写成「无来源」，不补零，也不从别的字段推断：理智药等药剂；凭证和各类券；逐关通关状态。这和 11 的「未知不补零」一致。以后找到来源时按新来源另行核对。
- [ ] 用户文档和读取结果写明两点：截至 2026-11-13 没有找到鹰角对第三方调用森空岛接口的公开表态；森空岛数据比游戏内实际状态滞后多久没有测过，快照的读取时间不等于游戏内的数据时间。
- [ ] 鉴权只用 09 保存的 token：用 token 换取访问凭证、请求签名和过期后的刷新都在读取器内部完成。刷新失败时报告凭据过期，交用户重新粘贴；不向用户索要密码。鉴权链和两级刷新的具体步骤，核实后采用。

待实现时核对的接口与字段：

| 账号事实 | 待核对的接口与字段 |
| --- | --- |
| 干员清单（精英化、等级、潜能） | `player/info` 的 `chars[]`；潜能从 0 计数 |
| 技能等级与专精 | `chars[].mainSkillLvl`、`skills[].specializeLevel` |
| 模组 | `chars[].equip[]` |
| 仓库物品 | `cultivate/player` 的 `items`；`player/info` 里没有 |
| 基建房间、驻员、心情 | `player/info` 的 `building`；心情满值 8,640,000 |
| 当前理智、公招槽位计时 | `status.ap`、`recruit[]` |
| 龙门币 | 上面的接口里还没有确认，来源待核对 |
| 理智药等药剂、凭证和各类券、逐关通关状态 | 没有找到来源 |

参考，只对照思路，不复制代码：鉴权链、请求签名、两级刷新和字段模型可参考 [FrostN0v0/nonebot-plugin-skland](https://github.com/FrostN0v0/nonebot-plugin-skland)（MIT）；森空岛清单转成 MAA 清单格式可参考 [OriginiumLab/MAA-PRTS](https://github.com/OriginiumLab/MAA-PRTS)（MIT）。

## 验证方式

使用网络边界替身覆盖成功、过期、缺字段和失败；同一合成账号经两来源产出可被同一工具读取的输入，并检查来源冲突及秘密泄漏。2026-11-13 补充：合成响应覆盖稀有度和潜能的两处转换、技能与模组字段的有和无，以及三类无来源事实在快照里的写法。

## 依赖理由

09 提供用户输入与内部读取凭据的方式；11 定义共享快照格式和写入位置。

## 实现与交付约定

有代码行为的改动先写外部行为测试，使用真实临时目录，只替代 MAA 进程、adb 和网络；skill 改动按同模型、同场景做前后评测，真模型只在本机运行。每个改动包经一个独立审查员审查，最多三轮，记录意见处置和结论；公开前检查所有移植文件及合成样例的隐私，经分支、PR 和 squash 合并。

构建与评测使用临时 home，不改动维护者现有 MAA、已安装 skill 或私有生产环境。沿用本票所列规格决定；新增或修改限制时在规格两张来源表登记来源。
